# Чекліст готовності Beauty Trainer до запуску

Актуально на **2026-10-18**. Цей список містить лише конкретну роботу, потрібну для запуску в компанії. Довгострокові можливості та експериментальні ідеї залишаються в [`IDEAS.md`](IDEAS.md).

Поточна база: 6 брендів, 64 лінійки, 208 продуктів; 22 модульні та 37 браузерних тестів. Застосунок готовий до контрольованого пілота, але ще потребує підготовки до запуску на всю компанію.

Позначення розміру: **S** — до одного робочого дня, **M** — кілька днів, **L** — окремий етап розробки.

## P0 — блокери запуску на всю компанію

### Доступ і безпека

- [x] **Реєстрація за корпоративним кодом запрошення** — M
  - Власник створює, змінює та вимикає код у налаштуваннях.
  - Реєстрація без чинного коду не створює акаунт.
  - Код зберігається на сервері у вигляді хешу й не потрапляє у frontend, Git або логи.
  - Вхід наявних користувачів не залежить від коду.
- [x] **Скидання пароля власником** — M
  - Власник створює одноразовий код або тимчасовий пароль для конкретного учасника.
  - Усі старі сесії учасника відкликаються.
  - Користувач мусить встановити новий пароль після першого входу.
  - Чинні паролі ніколи не відображаються в адмінці.
- [x] **Захисні HTTP-заголовки** — S
  - Додати CSP, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy` і `Permissions-Policy` для статичних сторінок.
  - Перевірити, що зображення, шрифти, API та production-збірка продовжують працювати.
  - Додати браузерну перевірку заголовків.
- [x] **Сторінка «Допомога та приватність»** — S
  - Пояснити, хто бачить прогрес, які дані зберігаються та як видалити акаунт.
  - Додати контакт власника для помилок у матеріалах і проблем із доступом.
  - Додати посилання зі вступної сторінки, форми входу й меню акаунта.

### Основний користувацький шлях

- [ ] **Скоротити мобільний каталог** — M
  - Початково показувати бренди, після вибору — лінійки, після вибору лінійки — продукти.
  - Не виводити всі 64 лінійки та 208 продуктів одним довгим полотном.
  - Зберегти пошук, фільтри, статуси навчання та прямі URL.
  - Перевірити desktop, 390 px і 320 px без горизонтального прокручування.
- [ ] **Єдина дія «Продовжити навчання»** — M
  - Dashboard автоматично обирає наступний корисний крок: нові картки, незавершений тест або заплановане повторення.
  - Користувач бачить коротке пояснення, чому запропоновано саме цей матеріал.
  - За відсутності прогресу система пропонує першу доступну лінійку.
- [ ] **Зрозумілий критерій завершення лінійки** — M
  - Визначити мінімальний результат звичайного та складного тесту.
  - Показувати, які кроки вже виконано та що залишилось.
  - Результати тесту мають вести до конкретної наступної дії.
  - Статуси «Нове», «Вивчається», «Час повторити», «Засвоєно» повинні відповідати цим правилам.

## P1 — перед пілотом або протягом першого тижня

### Якість навчання

- [ ] **Кнопка «Повідомити про проблему» біля запитання** — M
  - Користувач обирає причину: неправильна відповідь, незрозумілий текст, застаріла інформація або інше.
  - Власник бачить список звернень із брендом, лінійкою, продуктом і текстом запитання.
  - Повідомлення не впливає на результат тесту.
- [ ] **Діагностичний тест перед новою лінійкою** — M
  - Окремо позначати діагностику й не змішувати її з XP.
  - За результатом рекомендувати конкретні картки та продукти.
- [ ] **Режим розбору продуктів, які плутають** — M
  - Використати вже наявні пари плутанини.
  - Після відповіді пояснювати ключову відмінність між продуктами.
- [ ] **Покращити підсумок тесту** — S
  - Замість довгого переліку «сильних тем» показувати 3–5 ключових висновків.
  - Для кожної слабкої теми дати дію: відкрити картку, повторити продукт або пройти тест лінійки.

### Якість каталогу

- [ ] **Визначити пріоритетні для запуску бренди й лінійки** — S
  - Спочатку довести до повноти матеріали, які компанія рекламуватиме першими.
  - Не затримувати пілот через другорядні лінійки.
- [ ] **Додати спосіб застосування для пріоритетних продуктів** — L
  - Поточний звіт: 107 із 208 продуктів без окремого способу застосування.
  - Не вигадувати інструкції; переносити лише з підтверджених джерел.
- [ ] **Виправити слабкі та повторювані описи** — L
  - Поточний звіт: 72 продукти з коротким або повторюваним текстом.
  - Опис, призначення й переваги мають відповідати на різні запитання.
- [ ] **Замінити 9 низькороздільних фото milk_shake** — M
  - Використати оригінальні продуктові фото без генерації паковання.
  - Після заміни запустити `npm run images:audit`.
- [ ] **Джерело й статус перевірки матеріалу** — M
  - Для продукту зберігати URL/назву джерела, дату перевірки та статус «чернетка / перевірено».
  - Неперевірені матеріали позначати в адмінці, не перевантажуючи навчальний екран.

## P2 — після успішного пілота

### Керування командою

- [ ] **Групи користувачів** — L
  - Створення групи, додавання учасників і шаблон доступу до брендів та лінійок.
- [ ] **Навчальні плани** — L
  - Послідовність лінійок, дедлайн і відсоток виконання для групи та учасника.
- [ ] **Експорт результатів у CSV** — M
  - Логін, активність, XP, точність, засвоєні продукти, слабкі теми та дата останнього навчання.
- [ ] **Фільтри неактивності** — S
  - «Не входили 7 днів», «не навчались 14 днів», «не почали призначений план».
- [ ] **Журнал адміністративних дій** — M
  - Фіксувати зміну доступу, скидання пароля, видалення акаунта й імпорт каталогу.

### Аналітика продукту

- [ ] **Воронка першого дня** — M
  - Реєстрація → відкриття лінійки → картки → перший тест → завершення тесту.
- [ ] **Навчальні показники** — M
  - Активні учасники за 7/30 днів, повернення, середня точність, складні запитання та завершені лінійки.
- [ ] **Зворотний зв’язок після першого тижня** — S
  - Коротке опитування: що незрозуміло, що заважає й що найбільше допомагає.

## Пілот на 7–14 днів

- [ ] Запросити 5–15 працівників із різним рівнем знань.
- [ ] Призначити 1–2 конкретні лінійки, а не весь каталог.
- [ ] Перевірити, чи кожен самостійно реєструється та знаходить перше завдання.
- [ ] Перевірити, скільки людей завершили перший тест.
- [ ] Перевірити повернення на другий і сьомий день.
- [ ] Зібрати всі повідомлення про неправильні або незрозумілі запитання.
- [ ] Провести 3–5 коротких розмов із користувачами після пілота.
- [ ] Виправити повторювані проблеми перед запуском на всю компанію.

## Перевірка перед кожним production-запуском

- [ ] `npm run typecheck`
- [ ] `npm run lint`
- [ ] `npm test`
- [ ] `npm run build`
- [ ] `npm run test:e2e`
- [ ] Перевірити міграції D1 та застосувати лише нові міграції перед deployment.
- [ ] Перевірити вхід, реєстрацію, один тест і адмінку на production.
- [ ] Переконатися, що реєстрація відкрита або закрита згідно з планом запуску.
- [ ] Зафіксувати час deployment для можливого відновлення D1 через Time Travel.

## Умови готовності

### Готово до пілота

- Усі автоматичні перевірки проходять.
- Власник може допомогти учаснику відновити доступ.
- Учасник без пояснень знаходить перше навчальне завдання.
- Для вибраних пілотних лінійок перевірено тексти, відповіді й фото.

### Готово до запуску на всю компанію

- Закрито всі пункти P0.
- Пілот завершено без критичних проблем.
- Щонайменше 80% учасників пілота завершили перший тест.
- Є канал підтримки та процедура виправлення контенту.
- Власник може відновити доступ, обмежити матеріали й експортувати основний звіт.

### Готово до відкритого зовнішнього запуску

- Додатково перевірено політику приватності й правила використання матеріалів.
- Налаштовано власний домен, моніторинг помилок і довгострокове резервне копіювання.
- Проведено окремі accessibility та load-тести.

## Поза поточним обсягом

До завершення P0 не витрачати час на колесо фортуни, нові декоративні елементи, публічні рейтинги, додаткові типи запитань або детальне тестування складників. Вони не усувають основні ризики запуску.
